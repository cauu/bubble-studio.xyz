- 同一时间只允许一份 active spec。

- active spec 完成并附齐验收证据后，才能创建和激活下一份 spec。
- 已记录的需求、设计和结论不覆盖；范围变化通过 Change Log 追加，重大变化新建替代 spec。
- 一个事项对应一个 commit，commit 应包含 Spec ID、Item ID 和 Acceptance ID。

## 排队 Spec 轮廓

### S0002 主题中心页试点

目标是上线一个对用户有独立价值的公开主题中心页。默认候选为 Cardano staking 与 Pao Pool，但正式激活前必须先用 Search Console 或可核验的公开需求证据确定主题与查询边界。

预期事项：

- s2-01 收集查询、受众、搜索意图和现有页面证据。
- s2-02 确认主题中心的信息架构、URL 和非目标。
- s2-03 实现可见页面、直接答案、来源、相关产品和相关文章入口。
- s2-04 建立首页、项目页和相关文章的双向内部链接。
- s2-05 验证移动端体验、可访问性、结构化数据和索引信号。

### S0003 内容模板与主题网络

目标是让新旧文章稳定提供可抽取、可核验、可维护的信息，并围绕主题中心形成清晰的内部链接网络。

预期事项：

- s3-01 定义摘要、作者、发布日期、更新时间、来源和修订说明模板。
- s3-02 定义问题型标题、直接答案和内部链接规则。
- s3-03 选择与中心主题最相关的既有文章进行试点改造。
- s3-04 修正分类、标签、面包屑和相关文章关系。
- s3-05 验证重复内容、孤立页面和链接完整性。

### S0004 实体权威与证据一致性

目标是让 Pao Studio、Pao Pool、作者与开源项目在站内和可控制的外部渠道保持一致、可核验的实体关系。

预期事项：

- s4-01 建立组织和作者介绍页及稳定实体 ID。
- s4-02 补齐项目维护状态、源码、适用对象和可核验成果。
- s4-03 对齐网站、GitHub、CardanoScan 与社交资料中的品牌名称和描述。
- s4-04 为重要事实增加一手来源并记录冲突或未知项。
- s4-05 复核 Organization、Person、SoftwareApplication 等实体连接。

### S0005 测量与迭代

目标是建立可重复的 SEO 与 GEO 基线，依据观察结果决定后续实验，不承诺排名结果。

预期事项：

- s5-01 经用户确认后连接 Google Search Console 与 Bing Webmaster Tools。
- s5-02 记录收录率、非品牌曝光、查询、页面、CTR 与抓取问题基线。
- s5-03 建立有限、文件化的 AI 答案观察样本。
- s5-04 定义 28 天比较窗口、实验停止条件和回退标准。
- s5-05 形成首轮复盘并决定下一份 optimization spec。
